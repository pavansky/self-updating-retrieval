# When Accepted Answers Become Evidence: Feedback Loops in Self-Updating Retrieval

Code for the preprint (tex/main.pdf). All data is public CQADupStack (BEIR format, MTEB mirror on Hugging Face).

    uv venv -p 3.11 .venv && uv pip install -p .venv -r requirements.txt
    .venv/bin/python download.py              # 12 forums -> data/
    .venv/bin/python prep.py                  # BM25 + bge-small + MiniLM scores -> cache/ (~30 min on Apple MPS)
    .venv/bin/python sim.py 10 10             # 10 rounds, 10 orders, all forums -> results/sim_r10_all.json
    .venv/bin/python sim.py 20 10 unix,android,english,tex
    .venv/bin/python analyze.py sim_r10_all.json sim_r20_unix_android_english_tex.json
    .venv/bin/python make_tables.py           # LaTeX tables, macros and figures used by the paper
    cd tex && tectonic main.tex

Files: common.py (family construction, identical to the pilot), prep.py, sim.py (loop, safeguards, monitors,
exact per-entry attribution), analyze.py (paired CIs, crossovers, models, monitor AUROC), make_tables.py.
User acceptance is the only simulated component. Every number in the paper is generated by these scripts.

## Version 2 (October 2026, tex/main_v2.pdf)

v1 outputs are unchanged; v2 writes `*_v2` files.

    .venv/bin/python prep_v2.py askdoc                       # ask+thread entry embeddings -> cache/v2/
    .venv/bin/python prep_v2.py rerank android,unix,webmasters,mathematica   # cross-encoder scores (~30 min MPS)
    # sim_v2 records any (ask, thread) pair it has no embedding for; repeat prep_v2 askdoc + sim_v2 until it reports 0
    .venv/bin/python sim_v2.py 10 10 android,english,gaming,gis,mathematica,physics,programmers,stats,tex,unix,webmasters,wordpress bge,minilm,bm25 main
    .venv/bin/python sim_v2.py 10 10 android,mathematica,unix,webmasters ce ce
    .venv/bin/python analyze_v2.py sim_v2_main.json sim_v2_ce.json   # tables_v2.json, tex/*_v2.tex, macros_v2.tex, figs/*_v2.pdf
    cd tex && tectonic main_v2.tex

sim_v2.py reproduces sim.py exactly for question entries with constant acceptance, and adds entry-content variants
(ask / doc / askdoc), confidence-dependent acceptance, a confidence gate, a footprint retention rule, a cross-encoder
reranker and capture/steal diagnostics. analyze_v2.py also runs the split-order (5/5) out-of-sample test of the plug-in estimate.
